Box, Vec memory allocation#

Box#

Box is the simplest smart pointer in rust. It allocates a value on the heap and ensures ownership is clear and safe.

Under the hood, however, Box is defined with more complexity than the Box<T> we useally write. Here’s the actual definition:

#[lang = "owned_box"]
#[fundamental]
#[stable(feature = "rust1", since = "1.0.0")]
#[rustc_insignificant_dtor]
#[doc(search_unbox)]
// The declaration of the `Box` struct must be kept in sync with the
// compiler or ICEs will happen.
pub struct Box<
    T: ?Sized,
    #[unstable(feature = "allocator_api", issue = "32838")] A: Allocator = Global,
>(Unique<T>, A);

Box has two fields:

Unique<T>#

  • T: ?Sized: The type parameter T may be a dynamically sized type (DST).
    This bound allows Box to hold values like Box<dyn Trait> or Box<[u8]>, not only sized types.
  • Unique<T>: A wrapper around a raw non-null pointer that guarantees uniqueness.
    This ensures that the Box owns its allocation exclusively, preventing aliasing of the pointer.

A#

  • A: Allocator = Global: The type parameter A represents the allocator used to allocate and deallocate memory for the Box.
  • By default, it is set to Global, which means the global system allocator will be used. This does not introduce any runtime overhead because Global is zero size type (ZST)

At first glance, Box::new looks like an ordinary function:

#[must_use]
#[rustc_diagnostic_item = "box_new"]
#[cfg_attr(miri, track_caller)] // even without panics, this helps for Miri backtraces
pub fn new(x: T) -> Self {
    return box_new(x);
}

But if you look closely, Box::new doesn’t actually implement any allocation logic itself. Instead, it simply calls an external function: box_new(x).

So what is box_new?

1
2
3

#[rustc_intrinsic]
#[unstable(feature = "liballoc_internals", issue = "none")]
pub fn box_new<T>(x: T) -> Box<T>;

This is a compiler intrinsic. The #[rustc_intrinsic] attribute tells the compiler that box_new is not an ordinary function - it’s handled specially by the compiler. In practice, this gets lowered to a call to exchange_malloc, which is the real allocator entry point used for Box. Concretely, this gets lowered to a call to exchange_malloc.

Here’s example for calling Box::new.

1
2
3

fn main() {
    Box::new(true);
}

We can even see this in the compiled binary: what looks like a simple Box::new(true) in Rust turns into a raw call to exchange_malloc under the hood.

After compiling, you can actually see how Box::new(true) is lowered by the compiler. In the binary output below, notice the highlighted call to exchange_malloc — this is where the real allocation happens.

#[stable(feature = "drop_in_place", since = "1.8.0")]
#[lang = "drop_in_place"]
#[allow(unconditional_recursion)]
#[rustc_diagnostic_item = "ptr_drop_in_place"]
pub unsafe fn drop_in_place<T: PointeeSized>(to_drop: *mut T) {
    // Code here does not matter - this is replaced by the
    // real drop glue by the compiler.

    // SAFETY: see comment above
    unsafe { drop_in_place(to_drop) }
}

At first glance, this looks like an infinite recursion. It just calls itself again! But the comment reveals the trick:

  • The function body is just a placeholder.
  • The #[lang = "drop_in_place"] attribute marks it as a lang item, which the compiler recognizes specially.
  • When you compile, the compiler replaces this with real “drop glue”: the code that actually knows how to drop values of type T.

In the case of Box, this gets replaced with its Drop implementation:

#[stable(feature = "rust1", since = "1.0.0")]
unsafe impl<#[may_dangle] T: ?Sized, A: Allocator> Drop for Box<T, A> {
    #[inline]
    fn drop(&mut self) {
        // the T in the Box is dropped by the compiler before the destructor is run

        let ptr = self.0;

        unsafe {
            let layout = Layout::for_value_raw(ptr.as_ptr());
            if layout.size() != 0 {
                self.1.deallocate(From::from(ptr.cast()), layout);
            }
        }
    }
}

And, It’s call deallocate in Allocator trait. in this case it define in the Global.
